Overview

Quadruped locomotion is a demanding RL benchmark — it combines high-dimensional continuous control, complex contact dynamics, and strict failure conditions. This project starts from a minimal Isaac Lab baseline that only rewards velocity tracking and extends it with a set of principled modifications targeting stability, smoothness, and contact robustness.

The key insight is that velocity tracking alone as a reward is insufficient — a policy can satisfy it through jittery, energetically wasteful motions that fail immediately on harder terrain. The modifications introduced here add structured inductive biases (torque-based control, gait clocks, reward shaping) that guide the policy toward physically sensible locomotion without replacing tracking as the primary objective.

All training was run on NYU's Greene HPC cluster using SLURM, with PPO via the RSL-RL library. The submission includes a main branch (Parts 1–5 + Bonus 1) and a separate bonus branch for uneven terrain.

Baseline Limitations

Action Quality

No penalty on action rate or torque. Policy can improve reward via high-frequency joint changes that match velocity momentarily while producing jittery, energetically inefficient motion.

Contact Consistency

No representation of foot contact timing, swing clearance, or scuffing in observation or reward. Policies drag feet and fail to recover cleanly on uneven terrain.

Command Discontinuity

Commands sampled without smoothing — abrupt changes create a harder learning problem and encourage unstable corrective actions.

Actuation Model

Direct joint position targets without explicit torque computation or limits → behavior inconsistent under contact disturbances, no saturation awareness.

Gait Coordination

No timing information in the observation. Policy has no structured way to coordinate leg phases, leading to irregular stepping patterns.

Terrain Robustness

Trained only on flat ground. No termination for low base height, no contact-aware shaping. Performance degrades immediately on stairs or uneven surfaces.

Key Modifications

1 — Torque-Based PD Control with Saturation

Replaced direct joint position targets with a PD controller that computes and clips torques explicitly. This constrains actuation authority and trains the policy under physically meaningful saturation.

Torque computation
τ(t) = Kp(q_des(t) − q(t)) − Kd·q̇(t)
τ_clip(t) = clip(τ(t), −τ_max, τ_max)

2 — Command Smoothing via Low-Pass Filter

Target command resampled periodically from a uniform distribution. The executed command is smoothed with a first-order low-pass filter, reducing discontinuities in the objective.

Command smoothing (first-order IIR)
u_cmd(t+1) = α·u_cmd(t) + (1−α)·u_target(t)
α = exp(−Δt / τ)

3 — Gait Phase Clock Inputs

Augmented the observation with periodic gait phase features — sine waves with per-leg phase offsets. These provide timing information that helps the policy coordinate rhythmic stepping without explicit foot trajectory planning.

Clock features (4 legs)
c(t) = [sin(φ(t)+δ₁), sin(φ(t)+δ₂), sin(φ(t)+δ₃), sin(φ(t)+δ₄)]
φ(t) = 2πft

4 — Multi-Term Reward Shaping

Smoothness & Effort Terms

  • Action rate penalty: −λₐ‖aₜ − aₜ₋₁‖²
  • Torque magnitude penalty: −λ_τ‖τ_clip‖²
  • Joint velocity regularization
  • Angular velocity roll/pitch penalty

Stability & Contact Terms

  • Base height penalty (deviation from nominal)
  • Non-foot contact penalty (knees, hips, thighs)
  • Foot clearance / scuffing penalty
  • Raibert heuristic for coordinated stepping
  • Desired contact schedule shaping

5 — Bonus 1: Actuator Friction Randomization

Implemented per-episode friction torque randomization for sim-to-real robustness. Friction modeled as:

Friction torque model
τ_friction = F_s · tanh(q̇/0.1) + μ_v · q̇
μ_v ~ U(0.0, 0.3), F_s ~ U(0.0, 2.5) per episode

6 — Bonus 2: Uneven Terrain (separate branch)

Switched from flat plane to Isaac Lab terrain generator with rough terrain config and curriculum learning. Kept isolated on the bonus branch to preserve a clean main submission.

What I Learned

  • Reward shaping for locomotion is genuinely hard — each new term can have unintended interactions with existing ones, and a component breakdown is essential to verify the policy isn't exploiting a single term
  • Gait phase clocks are a lightweight but effective way to introduce temporal structure — the policy converges to more coordinated stepping without explicit foot trajectory planning
  • Torque-based PD control with saturation makes the policy more robust under contact disturbances — direct position targets are brittle when the robot hits obstacles
  • Command smoothing meaningfully reduces the difficulty of the learning problem — abrupt command changes create unnecessary instability in the early policy
  • Training stability diagnostics (entropy, loss curves, throughput) are necessary but not sufficient — task-level metrics (tracking error, fall rate, action smoothness) are what actually validate design choices
  • Running experiments on Greene HPC via SLURM taught me reproducible experiment management — proper seeding, logging, and rsync workflows for large-scale RL
