Overview

Manual CPR degrades in quality within 1–2 minutes due to rescuer fatigue. Existing automated devices are bulky, expensive, and not truly portable. This project set out to fix all three problems.

The result is a 3D-printed, FDM-manufactured portable CPR machine with a slider-crank compression mechanism, a FOC motor with real-time current feedback, a camera-guided placement system, and a touchscreen Kivy interface — all controlled by a Raspberry Pi 5 running a distributed software stack in C and Python.

The key differentiator: the AK60-6 FOC motor's current feedback lets the system infer chest stiffness and detect spontaneous breathing — adapting CPR delivery in real time rather than just running a fixed cycle.

Mechanical Design

The machine is a three-part FDM 3D-printed assembly, each component designed with a specific structural and functional role. The design went through 217 revisions — every iteration driven by real testing feedback.

Main Body — 80% Infill

Structural backbone housing the AK60-6 motor, slider-crank mechanism, and electronics hub. Internal compartmentalization isolates mechanics from electronics, concentrates failure points in one maintainable module.

Top Housing — 20% Infill

Lightweight enclosure for the 5-inch LCD touch display. Reduced infill minimizes weight while maintaining enough rigidity to protect the display under operational vibration.

Back Plate — 20% Infill

Encloses the rear assembly and mounts the emergency stop button for immediate accessible override. Designed for tool-free motor access.

Slider-Crank Mechanism

Converts AK60-6 rotary motion to linear chest compressions. 25mm linear bearings reduce friction, wear, and motor energy draw — directly improving compression consistency and component longevity.

Manufacturing

All parts manufactured via FDM 3D printing for rapid design iteration. 217 part revisions over the project — each addressing issues found in testing or improving fit, performance, and manufacturability.

Compression Pad

End-effector mounted on the slider for direct patient contact. Designed to distribute force across the sternum per AHA guidelines (~100 compressions/min, ~2-inch depth).

Hardware Architecture

Core Processing & Control

Raspberry Pi 5

  • Central processing unit running all operational logic
  • Manages touchscreen UI, camera, motor UART, and ZMQ IPC
  • Runs C motor control code and Python GUI concurrently
  • Powered via 5V/5A DC-DC converter from 22.4V LiPo

CubeMars AK60-6 FOC Motor

  • Field-Oriented Control for precise torque and speed
  • Real-time Iq phase current feedback via UART
  • Current integration (AmpSeconds) detects chest stiffness and breathing
  • UART at 115200 baud — custom frame: 0xAA header, CRC-16-Kermit, 0xBB tail
  • Logic level shifter required: Pi (3.3V) → Motor controller (5V)

Power System

22.4V LiPo Battery

  • High energy density for compact portable power
  • Powers motor directly at 22.4V
  • 5V/5A DC-DC converter steps down for Pi and electronics
  • Custom PDB manages distribution to all subsystems

Safety Systems

  • Emergency push button on back plate → immediate motor cutoff
  • 20A fuse on motor circuit → overcurrent protection
  • 12mm LED toggle switch as main power indicator
  • Appropriate gauge silicon wiring throughout for current capacity and flexibility

User Interface & Sensing

5-inch Touch Display

  • Primary HMI running Kivy application
  • Age profile selection (adult/kid)
  • Real-time stiffness and breathing status display
  • Camera-guided placement feedback with directional arrows
  • Confirms breathing detection before halting compressions

Raspberry Pi Camera 3 Wide

  • Wide-angle lens for expanded field of view
  • One-time shoulder calibration via Position_capture.py
  • Live OpenCV template matching for real-time shoulder detection
  • Vertical feedback: GOOD / UP / DOWN guides operator placement
  • Auto-advances to next screen after 1 second of confirmed "GOOD" placement

CPR Operation Sequence

01

Placement & Orientation

Camera guides operator to position device correctly over the patient's sternum. OpenCV template matching on live feed compares detected shoulder positions to calibration data. Arrow widget shows UP/DOWN/GOOD. Auto-advances when placement is confirmed for 1 second.

02

Profile Selection & Warm-Up

Operator selects Adult or Kid profile via touchscreen. Motor executes warmup_phase() — constant RPM run to bring system to operating temperature and verify mechanism function before patient contact.

03

Stiffness Calibration

calibration_cycle() performs slow oscillation and integrates motor current (AmpSeconds). If accumulated AmpSeconds exceed AMPSEC_THRESHOLD, chest is classified as "Stiff" — ERPM is adjusted accordingly (ERPM_MAX_STIFF vs ERPM_MAX_NORMAL). Status sent to GUI via ZMQ.

04

CPR Cycles

oscillate_cycles() drives motor between POS_CENTER_DEG ± POS_BAND_DEG with speed modulated by distance from center. After each set of cycles, hold_and_measure() holds the motor at zero RPM for HOLD_TIME_US while integrating current for breathing detection.

05

Breathing Detection & Confirmation

If holdAmpSec exceeds threshold during hold phase, system signals "breathing" to GUI. Operator confirms or overrides via touchscreen. If confirmed, motor enters permanent hold state. If overridden, CPR cycles resume.

Software Architecture

Distributed multi-process system using ZeroMQ for inter-process communication and MQTT for external telemetry. C handles real-time motor control; Python handles GUI, vision, and data forwarding.

Main_code.c

Motor Control & State Machine

Core C program on RPi5. UART motor comms at 115200 baud with custom CRC-16-Kermit frames. State machine: Init → Warmup → Profile Select → Placement → Stiffness Cal → CPR Cycles → Breathing Detect → Hold. Publishes telemetry (deg, Iq) via ZMQ PUB on port 5556. Receives GUI commands via ZMQ SUB on port 5561.

Touchdisplay.py

Kivy GUI + Camera Placement

Kivy ScreenManager navigates between: orientation/placement, age selection, stiffness display, CPR phase, breathing confirmation. OrientationScreen uses PiCamera2 + OpenCV template matching on shoulder_coords.json calibration. Arrow widget guides placement in real time. ZMQ PUB/SUB bridges with Main_code.c.

Position_capture.py

Camera Calibration Tool

One-time setup script. Captures a frame, user clicks left/right shoulders, coordinates saved to shoulder_coords.json with calibration image. Used by Touchdisplay.py's OrientationScreen to compute target chest Y position and crop shoulder templates for live matching.

Pos_cur_Monitoring.py

Real-Time Diagnostic Plot

Matplotlib + ZMQ SUB on port 5556. Receives raw telemetry from Main_code.c. Dual scrolling subplots: motor position (degrees) and smoothed Iq current (Amps) with moving average buffer. Standalone diagnostic tool for tuning control parameters.

Send_to_arduino.py

ZMQ → MQTT Bridge

Subscribes to ZMQ status stream from Main_code.c. Wraps each status in a JSON envelope with heartbeat flag, machine ID (CPR-03), and address. Publishes to MQTT broker at localhost:1883 on topic home/pi/data. Enables remote monitoring and Arduino integration.

gui_monitor.py

Remote Monitor GUI

customtkinter desktop app reading serial JSON from the machine. Displays: operational stage, breathing status (green/red dot), patient profile, chest stiffness, machine ID. Google Static Maps integration shows CPR machine location — clickable to open full Google Maps view.

Testing & Validation

Phase 1 — Pillow Test

Initial mechanical validation on a household pillow confirmed the compression mechanism, motor control, and 3D-printed structural integrity under load. Quickly identified that a pillow cannot simulate human chest compliance, chest stiffness sensing, or breathing detection.

Phase 2 — Prestan Manikin

Tested on a Prestan CPR training manikin — specifically designed to simulate adult chest compliance and anatomical landmarks. Adult profile selected, continuous CPR run for a 5-minute endurance test.

  • Machine successfully delivered compressions at target depth and rate throughout the test
  • FOC current feedback enabled accurate stiffness classification on the manikin's realistic compliance
  • At the 5-minute mark: shaft failure due to material mismatch — metal ball bearing + plastic shaft caused fracture under cyclical load
  • Key finding: shaft material must be upgraded to metal for production — currently being addressed in next iteration

What I Learned

  • Distributed software architecture with ZMQ IPC is the right approach for separating real-time motor control (C) from UI and vision (Python) — mixing them in one process causes timing issues
  • FOC current integration as a sensing modality is genuinely powerful — detecting chest stiffness and breathing from current alone, with no additional sensors, is elegant engineering
  • UART protocol debugging with a logic analyzer saved significant time — the AK60-6 documentation had discrepancies that only the analyzer revealed
  • 3D printing infill % is a real design variable — 80% vs 20% isn't just weight, it determines whether a part survives cyclical load
  • 217 revisions taught me that iterative design with short test cycles beats trying to get it right the first time
  • Material selection at joints under cyclic load is critical — the metal/plastic shaft interface failure at 5 minutes was entirely predictable in hindsight
