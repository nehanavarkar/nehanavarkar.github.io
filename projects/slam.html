Context

This SLAM navigation stack is built as part of my research at NYU's Generalizable Robotics & AI Lab (CILVR), where I work as a Research Assistant on the YOR platform — an open-source, sub-$10K mobile manipulator designed to democratize mobile manipulation research.

YOR needs to navigate previously unseen indoor environments autonomously while simultaneously performing manipulation tasks with its two arms. The navigation stack is the foundation that makes this possible — without reliable localization and mapping, the arm control and task planning built on top of it falls apart.

The stack integrates visual-inertial SLAM for pose estimation, dense voxel mapping for environment representation, and classical planning for collision-free navigation — all running in real time on onboard hardware.

System Architecture

The full navigation pipeline runs in four sequential stages — from raw sensor data to motor commands — all operating concurrently in a multi-threaded pipeline on Jetson/NUC hardware.

Stage 1 — State Estimation

VINS-Mono Visual-Inertial SLAM

VINS-Mono estimates robot pose using the ZED 2i stereo camera and ZED-SDK for odometry and loop closure. Combines visual features with IMU measurements for accurate 6-DOF pose estimation robust to fast motion. ZED-SDK provides high-quality stereo depth and odometry directly from the camera hardware.

Stage 2 — Dense Mapping

Real-Time Voxel Map

RGB and stereo depth from ZED 2i are converted to point clouds and integrated into a voxel map in the world frame at 5Hz. Voxel filtering and outlier rejection maintain map quality. Floor detection extracts the ground plane, and voxels are projected onto a 2D occupancy grid to create a global cost map — continuously updated with local cost maps from live point clouds.

Stage 3 — Path Planning

Weighted A* + Dynamic Replanning

A weighted A* planner generates collision-free paths through the global cost map. When a novel obstacle is detected (e.g., a walking human), the voxel occupancy is updated and a replan is triggered — producing a new collision-free path within one second. The planner uses both global cost map and live local cost map for reactive replanning.

Stage 4 — Control

Pure Pursuit with PID

Pure Pursuit path following controller executes planned trajectories on the omnidirectional swerve drive base. A lookahead point on the path is tracked continuously. PID control on base velocity ensures smooth execution. The decoupled translational and rotational control of the swerve drive simplifies navigation in cluttered spaces.

Hardware

ZED 2i Stereo Camera

Primary sensor for the entire navigation stack. Provides RGB, stereo depth, and IMU data. ZED-SDK handles hardware-accelerated depth computation, odometry, and loop closure detection onboard.

Jetson / NUC Compute

Multi-threaded pipeline runs all navigation modules concurrently — SLAM, mapping, planning, and control — on the onboard Jetson or NUC platform with real-time performance requirements.

Omnidirectional Swerve Base

YOR's base provides decoupled translational and rotational control — the robot can move in any direction without rotating first. This simplifies planning and control in cluttered indoor environments.

Telescopic Vertical Lift

63.5cm vertical range extends YOR's workspace from floor to overhead. The navigation stack integrates with the lift controller for whole-body coordination tasks.

Rerun Visualization

Live 3D visualization of the voxel map, robot pose, planned path, and sensor data during operation. Essential for real-time debugging, tuning the planner, and verifying SLAM accuracy.

Viser Visualization

Web-based 3D visualization for remote monitoring and teleoperation support. Provides an external view of the robot's internal state during autonomous operation.

Validation Demos

Tally-Mark Odometry Test

  • YOR marked a reference point on paper and returned to mark it once per loop
  • Robot traversed the full environment between each mark
  • After 10 loops: return marks within a 12mm radius of the initial mark
  • 12mm is well within the 50mm positional accuracy spec of the pipeline
  • Validates both odometry accuracy and loop-closure performance

Whole-Body Coordination Test

  • YOR held a ball in its gripper while the mobile base executed a lateral translation
  • Arm controller compensates for base movement in real time
  • End-effector deviation: 16mm — minimal tracking error under base motion
  • Demonstrates tight coupling between SLAM pose estimation and arm control
  • Critical for mobile manipulation tasks requiring simultaneous navigation and manipulation

Dynamic Obstacle Avoidance

  • YOR navigates toward a fixed goal while a walking human crosses the planned path
  • System detects the human in the live point cloud
  • Voxel occupancy updated → replan triggered within 1 second
  • New collision-free path generated around the human
  • Green path + red obstacles visible in internal voxel map visualization

Repeatability & Accuracy

  • Point-to-point navigation in previously unseen indoor environments
  • Real-time 3D map built from scratch on each new deployment
  • No pre-built maps required — fully online SLAM
  • Robust to dynamic environments and moving obstacles
  • Validated across multiple room configurations and obstacle layouts

What I Learned

  • Visual-inertial SLAM is significantly more robust than visual-only SLAM for fast-moving platforms — IMU fusion handles motion blur and rapid rotations that break feature tracking
  • Voxel map update rate (5Hz) is a critical tradeoff — faster updates improve obstacle detection but increase compute load; 5Hz was the right balance for the Jetson hardware
  • Pure Pursuit lookahead distance has an outsized effect on path smoothness vs. tracking accuracy — too short causes oscillation, too long causes corner-cutting
  • Building production-grade multi-threaded robotics pipelines in Python requires careful thread management — shared state between SLAM, planning, and control modules needs explicit synchronization
  • Real-time visualization with Rerun is invaluable for debugging sensor data — finding SLAM drift issues that weren't visible in position logs but were immediately obvious in 3D visualization
  • Whole-body coordination (nav + arm) requires much tighter pose estimation than navigation alone — the 12mm odometry accuracy was sufficient for navigation but borderline for manipulation precision
